# Дымовые тесты приложения

Пакет проверяет базовую работоспособность собранного приложения: интерфейс в Chromium
и связь с backend через Vite-прокси.

## Текущие проверки

В [app.smoke.test.ts](app.smoke.test.ts) проверяются:

- **Главная страница** — отображение на широком и узком экранах и переходы к готовым разделам.
- **Связь с backend** — запрос `/api/health` через Vite-прокси и проверка ответа по сгенерированному OpenAPI.
  Запрос выполняет сам тест; главная страница должна работать без обращений к API.

Визуальное соответствие макету проверяется отдельно: сравнение скриншотов в этот тест не входит.

`meeting-types.smoke.test.ts` проверяет создание владельцем и каталог гостя через публичный SDK,
ошибки полей с сохранением значений, загрузку, пустой результат, ошибку чтения и явный повтор,
блокировку отправки, узкий экран, клавиатуру и неизвестный адрес.

Успешные данные приходят от настоящего приложения. Сбои моделируются на транспортной границе:
при потере ответа сначала выполняется реальный POST, затем ответ отбрасывается;
отдельно проверяется ответ 500 после сохранения. Автоматических повторов POST нет.
Скриншоты успешного создания и каталога сохраняются в `/tmp/ticket10-*.png` для визуальной проверки.

`meeting-types.api.test.ts` проверяет настоящий NestJS через HTTP: пустой каталог, создание и порядок типов,
нормализацию, границы полей, одинаковые названия и ошибки структуры/JSON.
Статусы, Content-Type и реальные тела ответов сверяются со сгенерированным OpenAPI.

## Запуск

Из корня репозитория после установки зависимостей:

```sh
mise run test
mise run test:api
```

Команды пересобирают нужные приложения; `mise run check` включает оба набора. Тест запускает и останавливает серверы
на свободных портах; предварительно запускать приложения в dev-режиме не требуется.
Каждый независимый сценарий получает отдельный backend с пустым хранилищем.

`production.smoke.test.ts` запускает NestJS в production-режиме без Vite и проверяет раздачу SPA,
ошибки API и отсутствующих ресурсов, создание типа встречи, бронирование, список владельца и конфликт `409`.
Будущий слот выбирается из настоящей доступности. Если задан `DEPLOYMENT_URL`, этот отдельный тест
проверяет указанный сервис и создаёт данные в нём. Остальные тесты по этому адресу запускать не нужно.

`mise run test:docker` требует Docker Engine и Chromium. Команда собирает образ из корня,
проверяет автоматический запуск на двух `PORT`, пользователя `node`, production-сценарий в браузере
и сброс типов встреч и бронирований после перезапуска контейнера. Контейнеры удаляются после проверки.

`mise run setup` устанавливает зависимости и Chromium. Для отдельной установки браузера используйте
`mise run setup:browsers`.
